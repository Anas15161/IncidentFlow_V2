- 4.2 Synchronisation de session avec Keycloak en temps réel Dans l’architecture actuelle, les jetons JWT utilisés pour l’authentification sont sta- teless. Cela signifie qu’une fois émis par Keycloak, ils restent valides jusqu’à leur date d’expiration, même si l’état du compte utilisateur change entre-temps. 4.2.1 Problème actuel Cette caractéristique pose un risque de sécurité important. Si un utilisateur se connecte et reçoit un jeton valable pendant plusieurs minutes, ce jeton continue à être accepté par le backend Spring Boot tant qu’il n’est pas expiré. Un scénario critique peut alors se produire : 1. Un opérateur se connecte à l’application et obtient un jeton JWT valide pour une durée donnée. 2. L’administrateur détecte ensuite un comportement suspect et désactive immédiate- ment le compte de cet utilisateur dans Keycloak, ou lui retire son rôle d’accès. 3. Malgré cette action administrative, l’utilisateur peut encore appeler les API du backend pendant la durée de vie restante du jeton, car celui-ci demeure cryptogra- phiquement valide. Rapport de développement 4 Version 1.0IncidentFlow 4 AMÉLIORATIONS TECHNIQUES ET DEVOPS Autrement dit, le backend ne réinterroge pas Keycloak à chaque requête pour vérifier si le compte a été désactivé ou si les rôles ont été modifiés. Cela crée une fenêtre temporelle durant laquelle un utilisateur révoqué peut encore agir sur le système. Cette faiblesse ne remet pas en cause la validité cryptographique du JWT, mais elle limite la réactivité du système face à une révocation urgente de compte ou de privilèges. 4.2.2 Principe de la synchronisation temps réel Pour corriger cette limite, il est possible d’ajouter un mécanisme de synchronisation active entre Keycloak et le backend Spring Boot. L’idée consiste à faire remonter immé- diatement les événements d’administration sensibles depuis Keycloak vers l’application. Le principe est le suivant : — Keycloak détecte un év <truncated 229 bytes>  traite l’événement et invalide immédiatement la session logique de l’uti- lisateur concerné. 4.2.3 Architecture proposée L’implémentation peut reposer sur une chaîne simple et efficace. 1.
