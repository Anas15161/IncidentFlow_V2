Migration IAM vers Keycloak (V2) - Extraits de Code

1. Objectif et Philosophie

L'externalisation de l'Identity & Access Management (IAM) vers Keycloak vise à supprimer la gestion locale des utilisateurs et des mots de passe. Cette approche sécurisée (OAuth2 / OIDC) permet d'utiliser des jetons JWT asymétriques pour valider les accès, supprimant ainsi la vulnérabilité liée au stockage des mots de passe en base de données.

2. Infrastructure : Provisionnement Automatique (Docker)

Afin de garantir une intégration fluide, Keycloak est déployé via docker-compose.yml avec l'auto-importation du royaume (Realm) et de ses rôles composites au démarrage.

docker-compose.yml (Extrait)
  incidentflow-keycloak-v2:
    image: keycloak/keycloak:21.1.1
    command: start-dev --import-realm
    environment:
      KEYCLOAK_ADMIN: admin
      KEYCLOAK_ADMIN_PASSWORD: ${KC_PASSWORD}
    volumes:
      # Importation de la matrice RBAC et des rôles métiers au démarrage
      - ./keycloak/imports:/opt/keycloak/data/import
3. Backend (Spring Boot) : Standardisation OAuth2

Dans la V1, Spring Security était configuré pour valider des requêtes sur une base de données locale. Dans la V2, le standard OAuth2 Resource Server est implémenté. Le backend valide la signature cryptographique du JWT sans avoir à communiquer avec la base de données utilisateurs.

src/.../config/SecurityConfig.java (Extrait de la V2)
@Bean
@Profile("prod")
public SecurityFilterChain prodSecurityFilterChain(HttpSecurity http) throws Exception {
    http
        .csrf(AbstractHttpConfigurer::disable)
        .cors(cors -> cors.configurationSource(corsConfigurationSource()))
        .authorizeHttpRequests(auth -> auth
            .anyRequest().authenticated() // Sécurisation de tous les endpoints
        )
        // Délégation de l'authentification au jeton JWT généré par Keycloak
        .oauth2ResourceServer(oauth2 -> oauth2.jwt(jwt -> {}));
        
    return http.build();
}
4. Frontend (React) : Portails de Redirection IAM

Les interfaces complexes de création d'utilisateurs et de matrices de rôles (V1) ont été supprimées. Elles sont remplacées par des portails de redirection orientant les administrateurs vers la console Keycloak, marquant la séparation des préoccupations (Separation of Concerns).

src/components/UserManagementView.jsx (Nouvelle implémentation)
export function UserManagementView() {
  return (
    <div className="card">
      <h2>Centralisation des Identités</h2>
      <p>
        Toute la création d'utilisateurs, la réinitialisation de mots de passe, 
        et les politiques de sécurité sont désormais gérées dans <strong>Keycloak</strong>.
      </p>
      
      <a href="http://localhost:8181/admin" className="btn btn-primary">
        Ouvrir la Console Keycloak (IAM)
      </a>
    </div>
  );
}
5. Base de Données : Obsolescence des Tables Locales

En externalisant l'IAM, l'application réduit drastiquement sa responsabilité de stockage des PII (Personally Identifiable Information). Les tables locales users et roles ne sont techniquement plus requises pour l'authentification (seule une table de correspondance d'ID reste nécessaire pour la journalisation).
