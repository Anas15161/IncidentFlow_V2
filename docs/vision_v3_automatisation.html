01

Zero-Touch vs intervention humaine

L'automatisation ne remplace pas l'humain, elle filtre le bruit. Le système décide du routage.

Contexte
Un moniteur (Zabbix / Prometheus) crée l'incident via l'API d'IncidentFlow.
Problème
Tous les incidents ne sont pas automatisables : action physique, validation de sécurité, API prestataire en échec.
Solution
Le moteur DMN route vers une ServiceTask n8n ou une UserTask.
Résultat
Cas technique : 0 seconde d'intervention humaine.

Scénario 100 % automatisé

ServiceTask

Exemple : « Serveur Web Inaccessible ». Flowable détecte la criticité technique et invoque n8n, qui lance un script SSH pour redémarrer le serveur, puis clôture l'incident en base de données.

0 seconde d'intervention humaine

L'exception humaine (fallback)

UserTask

Exemple : « Imprimante physique défectueuse » ou « Échec du script SSH ».

  • Si une action physique est requise (remplacer du matériel).
  • Si une validation de sécurité est requise par un manager.
  • Si l'API du prestataire externe (ex : Société X) ne répond pas.
Le workflow BPMN quitte la boucle d'automatisation et génère une UserTask classique assignée à l'Administrateur local via Keycloak.
02

Impact sur le code et la base de données

Quelles modifications apporter concrètement au frontend, au backend et à PostgreSQL pour la V3 ?

Contexte
La V3 ajoute des actions exécutées par des machines sur des tickets existants.
Problème
Tracer l'historique des scripts n8n, éviter les conflits humain / machine, sécuriser les échanges.
Solution
Nouvelles colonnes, WebhookController, API Keys, dashboard et mode lecture seule.

Modifications Backend & DB

changement
  • PostgreSQL : ajout des colonnes , et dans la table Incident pour tracer l'historique des scripts n8n.
  • Spring Boot : nouveau Controller REST pour recevoir les callbacks asynchrones de n8n (ex : « Ticket clôturé par le prestataire »).
  • Sécurité : ajout de tokens API (API Keys) pour sécuriser les échanges entre Spring Boot et n8n sans passer par l'interface de login React.

Modifications Frontend (React)

React
  • Nouveau dashboard : une vue « Supervision IA/Auto » permettant à l'Admin de voir en direct les tickets en cours de traitement par les machines.
  • Lecture seule : si un ticket est is_automated=true, l'interface React verrouille le bouton « Traiter » pour éviter les conflits humain / machine.
03

Ressources et intégrations d'APIs

De quoi a-t-on besoin pour mettre en place ce centre névralgique automatisé ?

Contexte
n8n devient la couche d'intégration entre IncidentFlow et le monde extérieur.
Problème
Répliquer les incidents chez le sous-traitant, alerter l'astreinte, agir sur les serveurs.
Solution
Un conteneur n8n, une file Redis et des connecteurs ITSM, chat et infrastructure.

Infrastructures & ressources

docker-compose

L'intégration de la V3 requiert l'ajout du conteneur à notre fichier docker-compose.yml, ainsi qu'une base Redis supplémentaire pour gérer la file d'attente des webhooks.

APIs intégrées (exemples)

3 familles
  • Outils ITSM (Société X) : Jira Service Management ou ServiceNow. n8n utilise leurs APIs REST pour répliquer nos incidents dans le système du sous-traitant.
  • Communication : Slack API / MS Teams Webhooks, pour alerter les canaux d'astreinte IT avec des boutons d'action directs dans le chat (ex : « Approuver le redémarrage »).
  • Infrastructure : AWS EC2 / SSH / Ansible, pour exécuter des commandes de redémarrage ou de purge de mémoire si l'incident concerne un serveur.
04

Les gains architecturaux

L'impact direct de la séparation des responsabilités entre Java (métier) et n8n (intégrations).

Découplage extrême

Résultat
Le code Java de l'application reste pur. Pas besoin de coder ou de maintenir les SDK officiels de Slack ou Jira dans Spring Boot : l'intégration est déléguée visuellement à n8n.

Réduction du MTTR

Résultat
Le temps moyen de résolution (MTTR) chute. Les incidents critiques notifient les bons experts techniques et leurs systèmes, nuit et jour, instantanément.

Évolutivité facile

Résultat
Si la « Société X » change d'API, il n'est plus nécessaire de recompiler le backend Spring Boot : il suffit de modifier le flux visuellement, en glisser-déposer, sur n8n.
