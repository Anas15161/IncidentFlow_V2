Les 4 Piliers de l'Application

⚛️ Frontend (React / Vite)

Gère l'affichage, intercepte les requêtes API pour y injecter le token Keycloak automatiquement.

🍃 Backend (Spring Boot)

Point d'API REST. Protégé par Spring Security (OAuth2 Resource Server) qui valide les tokens.

⚙️ Flowable (Moteur BPMN)

Lit les fichiers XML pour créer un processus (ProcessInstance) par incident et assigne des tâches.

🔑 Keycloak (Serveur IAM)

Stocke les mots de passe de façon sécurisée, et synchronise les rôles comme "User Attributes".

Le Modèle "Shadow User" (Synchronisation Keycloak)

Comment l'application gère les rôles et la création d'utilisateurs en arrière-plan sans perturber le frontend.

1. L'Administrateur crée un compte React

L'Admin utilise l'interface React pour créer un collaborateur. Il choisit son email, nom, et son rôle local (ex: Résolveur).

2. Interception par UserService Spring Boot

Le backend sauvegarde l'utilisateur dans PostgreSQL (Shadow User) ET appelle immédiatement keycloakAdminService.createUserInKeycloak(...).

3. Création distante & Injection d'attributs Keycloak API

Via l'API REST admin-cli, Spring Boot crée le compte dans Keycloak. La prouesse technique ici est que le rôle local ("Résolveur") est poussé comme Attribut Personnalisé dans Keycloak.

4. Token Enrichi Keycloak JWT

Lors de la prochaine connexion de cet utilisateur, Keycloak génèrera un JWT contenant ce rôle dans le token. Spring Security le lira pour autoriser ou refuser l'accès aux APIs !

L'Orchestration des Tâches par Flowable

1. Démarrage de Processus Flowable

runtimeService.startProcessInstanceByKey("incidentWorkflow", variables) : Ce code charge le fichier XML. Flowable créé un contexte d'exécution unique pour ce ticket spécifique.

2. Les "UserTasks" Spring Boot

Le processus XML s'arrête sur une balise <userTask>. Flowable attend qu'un humain agisse. Le ticket est donc "En cours".

3. Transition (Clic sur un bouton) React

L'utilisateur clique sur "Résoudre" dans l'interface. React appelle l'API /incidents/transition.

4. Validation de la Tâche Flowable

Spring Boot trouve la tâche Flowable en attente via taskService.createTaskQuery() et appelle taskService.complete(taskId). Le moteur Flowable avance alors le pion sur le schéma XML jusqu'au prochain état (ex: "Clôturé") !
